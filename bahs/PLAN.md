# Bon Air Historical Society Website Redesign Plan

## Project goal

Create a modern, accessible, mobile-first website for the Bon Air Historical
Society that preserves the meaning and availability of its existing public
content. The redesign should make it easier for visitors to learn local
history, find events, become members, and contact the society.

Current site: <https://bonairhistoricalsociety.org/>

This is a non-public concept until the society grants permission to use its
content and publish any replacement site.

## Existing site inventory

The current navigation contains:

- Home
- Programs and Events
- About Us
- History
- Notable Bon Air Residents
- Links
- Contact Us
- Join

Before design or development begins, capture every page's text, images,
downloadable documents, external links, contact details, forms, and metadata in
a content inventory. Note the source URL for each item and flag missing,
outdated, or duplicate material for the society to review rather than silently
removing it.

## Audience and primary tasks

| Audience | What they need to do |
| --- | --- |
| Local residents | Explore Bon Air's history and discover events |
| Researchers and students | Find historical information, sources, and useful links |
| Potential members | Understand the society's mission and join |
| Current members | See programs, events, and membership information |
| Visitors with questions | Contact the society or request research assistance |

## Recommended site structure

Retain the existing content while organizing it around visitor tasks:

1. **Home** — mission, current/upcoming event, featured history, clear calls to action.
2. **About** — mission, history of the organization, leadership if supplied, and membership value.
3. **Explore Bon Air** — local history, notable residents, and related articles or stories.
4. **Events** — upcoming programs, past-program archive, event details, and calendar links.
5. **Research & Resources** — research help, useful links, documents, and any digitized material.
6. **Join & Support** — membership information, donation options if offered, and volunteer opportunities.
7. **Contact** — existing contact method, mailing address, research inquiry guidance, and response expectations.

Use redirects from every current page URL to its closest replacement page when
the new site launches.

## Design direction

- Use a warm, historically informed visual system: restrained heritage colors,
  readable serif display type, and highly legible sans-serif body type.
- Feature archival or local photography prominently, with captions and
  alt text supplied for every meaningful image.
- Make events and membership the primary calls to action without obscuring
  educational content.
- Use a consistent responsive layout with a simple mobile menu, generous
  spacing, and clear page titles.
- Avoid decorative design that resembles a period costume; the site should feel
  contemporary, trustworthy, and rooted in local history.

## Core page components

- Persistent header with logo/site name, primary navigation, and Join button
- Footer with mailing address, contact method, social links if available, and
  copyright statement
- Reusable event cards with date, title, location, summary, and detail link
- Featured-story cards for history and notable-resident content
- Accessible callout blocks for research inquiries, membership, and donations
- Breadcrumbs or clear section navigation for deep history/research pages
- Contact form with clear labels, validation, spam protection, and a privacy note

## Accessibility and quality requirements

- Meet WCAG 2.2 AA expectations for contrast, keyboard use, headings, focus
  indicators, forms, and image alternatives.
- Build and test at common phone, tablet, and desktop widths.
- Optimize and properly size images; avoid autoplaying media and unnecessary
  scripts.
- Use descriptive page titles, meta descriptions, headings, canonical URLs,
  and structured event data where appropriate.
- Maintain a plain-language privacy policy if the site collects form
  submissions, analytics, donations, or newsletter sign-ups.

## Content migration workflow

1. Obtain written permission from the society before copying content into a
   public site.
2. Create the page-by-page inventory and identify the authoritative source for
   each item.
3. Move content into the proposed structure without changing facts or
   historical wording unless the society approves edits.
4. Rewrite only presentation elements—headings, summaries, navigation labels,
   image captions, and calls to action—after approval.
5. Have a society representative review all historical facts, names, dates,
   images, and event details before launch.
6. Preserve or redirect existing URLs and submit the new sitemap after launch.

## Technical approach

For a small volunteer-maintained site, use a low-maintenance CMS with an
editor-friendly event workflow. A modern WordPress build, Squarespace, or a
static site backed by a lightweight CMS are reasonable options; select one only
after confirming who will maintain content, the budget, existing hosting and
domain access, and any donation or mailing-list integrations.

The concept phase can use static mock data and placeholder images. Do not
publish copied content, logos, or images without permission.

## Deliverables

- Sitemap and content inventory
- Desktop and mobile home-page concept
- Reusable page designs for history article, event detail, research/resources,
  join/support, and contact
- Clickable prototype or working staging site
- Content migration checklist and redirect map
- Accessibility, responsive-design, and link-check results
- Editor handoff guide and launch checklist

## Suggested project sequence

| Phase | Outcome |
| --- | --- |
| Discovery | Permission, stakeholder goals, content inventory, technical constraints |
| Information architecture | Approved sitemap, navigation, and page priorities |
| Visual design | Design system and responsive page concepts |
| Build | Reusable templates, CMS configuration, forms, and responsive implementation |
| Content migration | Reviewed content, images, documents, metadata, and redirects |
| Quality assurance | Accessibility, browser, device, form, performance, and link checks |
| Launch and handoff | Backup, DNS/hosting transition, analytics, editor training, and post-launch review |

## First outreach milestone

Prepare a one-page private home-page concept using neutral placeholder content
or a clearly labeled visual mockup. Ask the society whether it is interested in
reviewing a modernization concept that preserves its existing content and gives
its representatives final approval over every historical detail.
